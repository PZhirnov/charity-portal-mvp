🚀 Шпаргалка: запуск фронтенда и окружение
1. Первый запуск (один раз)
bash
cd frontend          # или куда положили Next.js
npm install          # установить зависимости
cp .env.example .env.local   # если есть шаблон
Если .env.example нет — создайте .env.local вручную (см. раздел 3).

2. Ежедневный запуск
Терминал 1 — бэкенд (FastAPI):

bash
cd backend
source venv/bin/activate      # Linux/macOS
# venv\Scripts\activate       # Windows
python run.py                 # или: uvicorn main:app --reload --port 8000
Терминал 2 — фронтенд (Next.js):

bash
cd frontend
npm run dev
Открыть: http://localhost:3000
Документация API: http://localhost:8000/docs

Два терминала — нормально. Можно запускать в фоне (& / start), но так вы видите логи обоих.

3. Файл .env.local (в корне frontend/)
bash
# Адрес FastAPI для Server Components и Route Handlers.
# Браузер эту переменную НЕ видит (нет префикса NEXT_PUBLIC_).
API_URL_INTERNAL=http://localhost:8000

# Если нужна переменная в браузере — только с префиксом:
# NEXT_PUBLIC_API_URL=http://localhost:8000
Правила:

.env.local не коммитится (уже в .gitignore).

После изменения — перезапустить npm run dev. Next.js не подхватывает env на лету.

В Docker Compose для сервиса frontend задайте API_URL_INTERNAL=http://backend:8000 (имя сервиса, не localhost).

.env.local имеет приоритет над .env и .env.development.

4. Проверка, что всё связано
Проверка	URL	Ожидание
FastAPI жив	http://localhost:8000/docs	Swagger открывается


5. Частые проблемы и решения
npm run dev падает с EADDRINUSE — порт 3000 занят:

bash
npm run dev -- -p 3001
fetch failed в Server Component — FastAPI не запущен, или в .env.local указан backend:8000 вместо localhost:8000 (это имя работает только внутри Docker).

ModuleNotFoundError: No module named 'fastapi' — не активировано venv:

bash
cd backend && source venv/bin/activate
uvicorn: command not found — venv не активирован или uvicorn не установлен:
